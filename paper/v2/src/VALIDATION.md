# Validation of the v2 build and checks (builder B2, 2026-10-11)

What ran in this session, what each check reported, and the negative
controls: every check below is listed with a run in which it **failed where
it should**, unless the last section says otherwise. All runs used scratch
copies under this session's scratchpad (`B2/val/…`); nothing in
`paper/v2/sections/` was touched. The repository outputs of a v2 build are
regenerated by every run, so the numbers here are the record.

## Environment of every kit run

- Kit: `tmlr-beyond-pdf-author-kit.zip` fetched fresh into a new, empty
  directory per run; sha256 `e531434b…bacc2d5` verified each time (21 runs).
- Merge: the kit's own `merge_files()` (via `kit_merge.py`, `python3 -I`).
  Build: local Ruby 3.3.6, `bundle install` into a scratch gem directory
  (`B2/gems`, a scratch-only install, needed because this container had no
  gems and no Docker), resolving github-pages 232, jekyll 3.10.0, kramdown
  2.4.0, kramdown-parser-gfm 1.1.0; `LANG=C.UTF-8 bundle exec jekyll build
  --future`, exit 0 in every run.
- Inspection: `http-server` 14.1.1 and headless Chromium (playwright 1.56.1,
  the preinstalled browser). Outbound requests went through the session proxy.
  One fix was needed: Playwright forces loopback through a proxy, so the first
  run fetched the proxy's error page instead of the site;
  `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK=1` is now set by the
  scripts.

## Not negative-controlled, and why

- **MathJax errors, partly.** The first two `sab1` runs did **not** count the
  planted `$\undefinedmacro{x}$`: MathJax's `noundefined` extension draws an
  undefined macro as red text (no `mjx-merror`), and CHTML draws glyphs with
  CSS, so the element has no text to match. The check now also counts
  containers whose assistive MathML has `mtext mathcolor="red"`, and the last
  `sab1` run FAILED on it as it should. A TeX syntax error (`mjx-merror`) was
  not planted, so that branch is not negative-controlled.
- **Print companions shown in print media** and **the zip**: both verify the
  staging and the kit's own CSS; no planted defect can make them fail without
  breaking the stager itself. The zip's entries and top-level name are read
  back each run.
- **Page-level horizontal overflow** (the second half of the overflow check):
  Distill's `d-article` has `overflow-x: hidden` and `contain: layout`, so no
  content inside the article can widen the page; the check's 0 px is expected
  by construction, and a failure would mean a kit or `_styles` change.
- **Bib `%` lines staged** cannot be made non-zero without breaking the stager;
  the check reads the staged file back (12 → 0 on the old bib).
- **Footnote placement, byline text, math counts and console errors** are INFO
  by design: they report, they do not grade.
